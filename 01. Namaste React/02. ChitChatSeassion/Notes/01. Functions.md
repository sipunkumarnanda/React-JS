
# 🚀 JavaScript Arrow Functions & `this` (Interview Notes)

---

# 📌 1. How does JavaScript know about the `function` keyword?

### Interview Answer

> The `function` keyword is built into the JavaScript language. Every JavaScript engine (like **V8**, **SpiderMonkey**, or **JavaScriptCore**) understands this keyword because it is part of the JavaScript specification (ECMAScript).

When the JavaScript engine reads your code and encounters the `function` keyword, it knows that a function declaration is being created.

```js
function x() {
    const a = 10;
}
```

The engine immediately recognizes this as a function declaration.

---

# 📌 2. How does the JavaScript engine execute code?

The JavaScript engine doesn't execute your code immediately.

It performs **two phases**.

## 🟢 Phase 1 - Memory Creation Phase

During this phase, JavaScript scans the entire program.

It allocates memory for:

* Variables
* Functions

Example

```js
function x() {}

var xyz = 30;
```

Memory looks like

```
Memory

x   -> Complete Function
xyz -> undefined
```

Notice that:

* Function declarations are stored with their complete definition.
* `var` variables are initialized with `undefined`.

This behaviour is called **Hoisting**.

---

## 🔵 Phase 2 - Execution Phase

Now JavaScript starts executing the code line by line.

```js
var xyz = 30;
```

Now

```
xyz -> 30
```

When it reaches

```js
x();
```

A **Function Execution Context** is created.

---

# 📌 3. What is a Function Execution Context?

Whenever a function is called,

```js
x();
```

JavaScript creates a brand new execution context.

It contains

✅ Local Memory

```js
const a = 10;
```

✅ Function Code

✅ Scope Chain

✅ `this`

After the function finishes,

the execution context is destroyed.

# 📌 4. Local Variables

```js

    const a = 10;
}
```

`a` is called a **local variable** because it only exists inside `x()`.

Outside the function

```js
console.log(a);
```

❌ Error

```
ReferenceError
```

because `a` no longer exists.

# 📌 5. Anonymous Function

An anonymous function is simply a function **without a name**.

```js
function () {

}
```

❌ This is invalid because JavaScript expects a name after the `function` keyword.

Instead we usually assign it to a variable.

```js
var y = function () {
    console.log("Hello");
};
```

Now JavaScript stores the function inside `y`.

---

# 📌 6. Function Expression

```js
var y = function () {
    console.log("Hello");
};
```

This is called a **Function Expression**.

Why?

Because the function is created as part of an expression and assigned to a variable.

# 📌 8. Arrow Functions (ES6)

Arrow Functions were introduced in **ES6 (ECMAScript 2015).**

Many modern features came in ES6:

✨ let

✨ const

✨ Arrow Functions

✨ Promises

✨ Classes

✨ Template Literals

✨ Spread Operator

✨ Rest Operator

✨ Destructuring

✨ Modules

---

Old Syntax

```js
function add(a,b){
    return a+b;
}
```

Arrow Function

```js
const add = (a,b)=>{
    return a+b;
}
```

Even Shorter

```js
const add = (a,b)=>a+b;
```

# 📌 11. The Biggest Difference - `this`

This is the most frequently asked interview question.

---

## Normal Function

```js
const obj = {

    fn:function(){
        console.log(this);
    }

}
```

Calling

```js
obj.fn();
```

Output

```
obj
```

### Why?

Normal functions get their `this` value from **how they are called**.

Since

```js
obj.fn()
```

is called using `obj`,

```
this = obj
```

---

## Arrow Function

```js
const obj = {

    fn2:()=>{

        console.log(this);

    }

}
```

Calling

```js
obj.fn2();
```

Browser

```
Window
```

Node.js

```
{}
```

### Why?

Arrow functions **do not create their own `this`.**

Instead,

they inherit `this` from their surrounding (lexical) scope.

---

# 📌 12. Lexical `this`

Lexical means

👉 Take `this` from the parent scope.

Example

```js
const obj={

    fn:()=>{

        console.log(this);

    }

}
```

There is no `this` inside the arrow function.

So JavaScript looks outside.

Top level in Browser

```
Window
```

Top level in Node.js module

```
{}
```

| Browser                                       | Node.js                                |
| --------------------------------------------- | -------------------------------------- |

# 📌 16. Interview Questions

## ❓What is an Arrow Function?

**Answer**

Arrow functions are a shorter syntax for writing functions introduced in ES6. They do not have their own `this`; instead, they inherit `this` from their surrounding lexical scope.

---

## ❓What is the difference between a normal function and an arrow function?

**Answer**

Normal functions have their own `this`, which depends on how they are called. Arrow functions do not have their own `this`; they inherit it from the surrounding scope.

---

## ❓What is a Function Expression?

**Answer**

A function expression is a function assigned to a variable.

```js

```

---

## ❓What is an Anonymous Function?

**Answer**

An anonymous function is a function without a name.

Example

```js
const greet = function(){

};
```

---

## ❓What is Hoisting?

**Answer**

Hoisting is JavaScript's behaviour of moving declarations to the top of their scope during the memory creation phase.

* Function declarations are hoisted with their full definition.
* `var` variables are hoisted and initialized with `undefined`.
