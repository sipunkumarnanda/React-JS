## what is DOM elem vs React Elem ?

* ✅ HTML elements become DOM elements when the browser parses the HTML and creates the DOM tree.

### A React Element is a JavaScript object that describes what you want to see on the UI.

* It is a lightweight description of a UI element.
* It is **not** a real HTML element and **not** a DOM element.
* Example:
  `React.createElement("h1", { key: "heading1" }, "React Heading 1")`

## React Elem is a JS object

* When we render it to the DOM, it becomes an HTML element.
* How can we see it?

  * By doing `console.log()`.

## How do we render it?

```js
const root = ReactDOM.createRoot(document.getElementById("root"));
```

Inside:

```js
root.render();
```

## When we do `root.render(container)` and pass the React Element (object) into it, the powerful ReactDOM library takes this object, converts it into an HTML element, and renders it in the browser.

* "Push" here means it replaces everything that is inside the root with whatever I am rendering from here.
* It will **replace**, not **append**.

## `React.createElement("h1", { key: "heading1" }, "React Heading 1")` is not a good way to write React Elements.

* The syntax is very messy.
* Which is easier?

  * `React.createElement()`
  * or `<h1></h1>`?
* When React was built, this was the core of React.
* But soon React developers realized that if we were going to create every `h1`, `div`, `span`, etc. like this, it was not going to work.
* It was not developer-friendly.
* It was very hard to write and maintain.
* So what can we use now?
* Facebook developers created **JSX**.
* What is JSX?
* JSX is a JavaScript syntax that makes it easier to create React Elements.

## Lots of React developers think JSX is part of React, but that is not correct.

* React is different.
* JSX is different.
* Lots of developers think React cannot be written without JSX.
* That is wrong.
* We can build a React application without using JSX by using `React.createElement()`.

## Before React and other frameworks existed, we used to have basic HTML, CSS, and JavaScript in separate files.

* We wrote all the code separately.
* These frameworks and libraries tried to merge everything together so that we could build the UI more easily in one place.

## JSX heading

```jsx
const jsxHeading = <h1>Namaste React Using JSX 🚀</h1>;
```

* Does this look familiar?
* Is this HTML inside JavaScript?
* No, it is **not** HTML inside JavaScript.
* It is **JSX**.
* JSX is an HTML-like syntax, not HTML.
* It looks like XML, but it is **not** XML either.
* `<h1>Namaste React Using JSX 🚀</h1>` becomes a React Element.
* JSX is just the syntax.
* React Element is the object.

## `const jsxHeading = <h1>Namaste React Using JSX 🚀</h1>;` Is this valid JavaScript?

* This is **not** pure JavaScript.

* JavaScript does not come with JSX built into it.

* The JavaScript engine does not understand JSX.

* JavaScript understands ES (pure JavaScript), which the JavaScript engine and browser understand.

* Then how is this code working?

* Parcel is doing the work behind the scenes.

* This code is written by us, but before it reaches the JavaScript engine, it is transpiled.

* Then the JavaScript engine receives code that the browser understands.

* JSX code is transpiled before it reaches the JavaScript engine.

* Transpiled means this code is converted into code that the browser can understand.

* Will ReactDOM understand JSX?

```jsx
root.render(<h1>Namaste React Using JSX 🚀</h1>);
```

* No, ReactDOM will not understand this code.
* Who is transpiling this code?
* Parcel.
* Is Parcel itself transpiling the code?
* No.
* Parcel gives the responsibility of transpiling to a package called **Babel**.
* What is Babel?
* It is a normal JavaScript package.
* Who installed it?

  * Parcel.
* As soon as I write JSX:

```jsx
<h1>Namaste React Using JSX 🚀</h1>
```

and save the file:

* Parcel rebuilds the project.
* Babel converts this code into code that React understands.
* Think of Babel as a black box for now.
* Babel was **not** created by Facebook.

## How is this code running?

* `React.createElement()`
* Returns a React Element.
* It is a JavaScript object.
* Then it is rendered by ReactDOM.
* Finally, it is converted into an HTML element.

## How does JSX work?

* JSX code is transpiled into `React.createElement()` by Babel.
* `React.createElement()` returns a JavaScript object.
* The object is rendered by ReactDOM.
* Finally, it is converted into an HTML element.

## You can call Babel a transpiler or a JavaScript compiler, whichever you prefer.

## How does Babel transpile?

* It reads the code token by token.
* It creates an Abstract Syntax Tree (AST), and so on.

## All the attributes we write in JSX should be in camelCase.

## If you want to write JSX in multiple lines, you have to wrap it inside parentheses.

## What is a React Component?

* You may have heard people say that everything in React is a component.
* There are two types of components in React:

  1. Class-based components (old way of writing React code) — nobody uses them much today.
  2. Functional components (new way of writing React code).

# What is a React Functional Component?

* It is just a normal JavaScript function.
* A React Functional Component is a JavaScript function that returns JSX.

# React Element vs React Component

```jsx
const HeadingComponent = () => {
  return (
    <div id="container">
      <h1>Namaste React Functional Component 🚀</h1>
    </div>
  );
};
```

## How to render `HeadingComponent` into the root?

```js
root.render(HeadingComponent());
```

or

```jsx
root.render(<HeadingComponent />);
```

## What is Component Composition?

* Putting one component inside another component.

```jsx
const HeadingComponent = () => {
  return (
    <div id="container">
      <Heading />
      <h1>Namaste React Functional Component 🚀</h1>
    </div>
  );
};
```
