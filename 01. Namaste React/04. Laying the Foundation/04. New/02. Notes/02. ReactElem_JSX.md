# 🌐 What is a DOM Element vs a React Element?

* ✅ HTML elements become **DOM elements** when the browser parses the HTML and creates the DOM tree.

### ⚛️ A React Element is a JavaScript object that describes what you want to see on the UI.

* It is a lightweight description of a UI element.
* It is **not** a real HTML element.
* It is **not** a DOM element.

Example:

```js
React.createElement("h1", { key: "heading1" }, "React Heading 1");
```

---

## ⚛️ React Element is a JavaScript Object

* When we render it to the DOM, it becomes an HTML element.
* How can we see it?

  * By doing `console.log()`.

---

## 🖥️ How do we render it?

```js
const root = ReactDOM.createRoot(document.getElementById("root"));
```

Inside:

```js
root.render();
```

---

## ⚙️ What happens when we do `root.render(container)`?

* We pass the React Element (a JavaScript object) into `root.render()`.
* The powerful **ReactDOM** library takes this object, converts it into HTML elements, and renders it in the browser.
* "Push" here means it **replaces everything** inside the root element with whatever we are rendering.
* It **replaces**, not **appends**.

---

## 🤔 Is `React.createElement()` a good way to write React Elements?

```js
React.createElement("h1", { key: "heading1" }, "React Heading 1");
```

* This is not a very convenient way to write React Elements.

* The syntax is quite messy and difficult to read.

* Which is easier?

  * `React.createElement()`
  * or `<h1></h1>`?

* When React was first built, `React.createElement()` was the core API.

* But React developers soon realized that creating every `h1`, `div`, `span`, etc., like this was not developer-friendly.

* It was difficult to write and maintain.

So, what can we use instead?

👉 Facebook developers introduced **JSX**.

---

## ✨ What is JSX?

* JSX is a JavaScript syntax that makes it much easier to create React Elements.

---

## ⚠️ JSX is NOT React

Many React developers think JSX is part of React.

❌ That is **not** correct.

* React is different.
* JSX is different.

Many developers also think you cannot write React without JSX.

❌ That is also wrong.

You can build a React application **without using JSX**, by using `React.createElement()`.

---

## 📜 Before React

Before React and other frameworks existed:

* We had separate HTML, CSS, and JavaScript files.
* We wrote everything separately.

Frameworks and libraries tried to bring everything together so that we could build UI more efficiently in one place.

# ✨ JSX Heading

```jsx
const jsxHeading = <h1>Namaste React Using JSX 🚀</h1>;
```

Does this look familiar?

Is this HTML inside JavaScript?

❌ No.

It is **JSX**.

* JSX is an HTML-like syntax.
* It is **not** HTML.
* It looks similar to XML, but it is **not** XML either.

```jsx
<h1>Namaste React Using JSX 🚀</h1>
```

This piece of code becomes a **React Element**.

* JSX is just the syntax.
* React Element is the JavaScript object.

---

## 🤔 Is this valid JavaScript?

```jsx
const jsxHeading = <h1>Namaste React Using JSX 🚀</h1>;
```

* ❌ This is not pure JavaScript.
* JavaScript does not have JSX built into it.
* The JavaScript engine does not understand JSX.
* JavaScript engines only understand standard ECMAScript (ES).

Then how is this code working?

👉 Parcel is doing the work behind the scenes.

* We write JSX.
* Before this code reaches the JavaScript engine, it is **transpiled**.
* Then the JavaScript engine receives code that it understands.

👉 JSX is transpiled before it reaches the JavaScript engine.

Transpiled means:

* The JSX code is converted into JavaScript code that browsers can understand.

---

## 🤔 Will ReactDOM understand JSX?

Example:

```jsx
root.render(<h1>Namaste React Using JSX 🚀</h1>);
```

❌ No.

ReactDOM does not understand JSX.

---

## 🤔 Who transpiles JSX?

Is it Parcel?

Not exactly.

Parcel gives the responsibility of transpiling JSX to another package called **Babel**.

---

## 📦 What is Babel?

* Babel is a normal JavaScript package.
* Who installed it?

  * 👉 Parcel.

As soon as you write JSX like:

```jsx
<h1>Namaste React Using JSX 🚀</h1>
```

and save the file:

* Parcel rebuilds the project.
* Babel converts the JSX into code that React understands.

You can think of Babel as a **black box** for now.

👉 Babel was **not** created by Facebook.

# 🔄 How does JSX work?

```text
JSX
 ↓
Transpiled by Babel
 ↓
React.createElement()
 ↓
JavaScript Object
 ↓
Rendered by ReactDOM
 ↓
Converted into HTML Elements
```

---

You can call Babel either:

* a **Transpiler**, or
* a **JavaScript Compiler**.

Both are commonly used.

---

## ⚙️ How does Babel transpile?

* It reads the code token by token.
* It creates an Abstract Syntax Tree (AST).
* It transforms the AST.
* Then it generates JavaScript code.

---

## 📝 JSX Rules

* All attributes written in JSX should be in **camelCase**.

* If you want to write JSX across multiple lines, wrap it inside parentheses.

# ⚛️ What is a React Component?

You may have heard people say:

> "Everything in React is a component."

There are two types of components in React:

1. **Class Components** (the old way of writing React)
2. **Functional Components** (the modern way of writing React)

---

# 🚀 What is a React Functional Component?

* It is just a normal JavaScript function.
* A React Functional Component is a JavaScript function that returns JSX.

---

# ⚛️ React Element vs React Component

```jsx
const HeadingComponent = () => {
  return (
    <div id="container">
      <h1>Namaste React Functional Component 🚀</h1>
    </div>
  );
};
```

---

## 🖥️ How do we render `HeadingComponent` into the root?

```js
root.render(HeadingComponent());
```

or

```jsx
root.render(<HeadingComponent />);
```

---

# 🧩 What is Component Composition?

👉 Putting one component inside another component.

```jsx
const HeadingComponent = () => {
  return (
    <div id="container">
      <Heading />
      <h1>Namaste React Functional Component 🚀</h1>
    </div>
  );
};
```

---

## 🤔 Can we use a normal function?

✅ Yes.

We can use a normal JavaScript function as a React component.

## 🔒 JSX Prevents XSS Attacks

```js
const api = api.getData();
```

Inside JSX:

```jsx
{api}
```

We are injecting data here.

If malicious data comes from the API and tries to execute harmful JavaScript (XSS attack):

* It can try to steal cookies.
* It can access session storage.
* It can perform many other malicious actions.

✅ But JSX takes care of injection attacks.

* JSX automatically escapes the values.
* It sanitizes the content before rendering it.
* This helps protect your application from XSS attacks.
