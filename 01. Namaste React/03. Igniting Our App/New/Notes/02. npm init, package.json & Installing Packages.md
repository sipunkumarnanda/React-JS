# 🌟 1. Why Do We Need npm in a Project?

Imagine you're building an **online food delivery app**.

You need:

* React
* Parcel
* Axios
* React Router
* Redux
* Tailwind CSS

Without npm, you'd have to:

* Download each library manually.
* Keep track of their versions.
* Update them yourself.
* Manage their dependencies.

That would be extremely difficult.

👉 npm automates all of this.

```

      │
      ▼

```

# 🚀 2. What is `npm init`?

When starting a new project, npm doesn't know anything about it.

Run:

```bash
npm init
```

npm will ask questions such as:

```text
package name:
version:
description:
entry point:
author:
license:
```

After answering, it creates a **`package.json`** file.

---

## Shortcut

Instead of answering every question:

```bash
npm init -y
```

The `-y` flag means:

> **"Yes to all default values."**

npm automatically creates a default `package.json`.

---

## Example

```bash
mkdir food-ordering-app
cd food-ordering-app

npm init -y
```

Your project now looks like:

```
📁 food-ordering-app

├── package.json
```

# 📝 3. What is `package.json`?

## Definition

`package.json` is the **heart of every Node.js project**.

Think of it as your project's **identity card**.

It stores:

* Project name
* Version
* Description
* Scripts
* Dependencies
* Dev dependencies
* Author
* License

---

## Real-world Analogy 🪪

Imagine your passport.

It contains:

* Your name
* Nationality
* Date of birth
* Passport number

Similarly,

`package.json` contains your project's information.

```
Project

↓

package.json

↓

Identity Card
```

---

## Example

```json
{
  "name": "food-ordering-app",
  "version": "1.0.0",
  "description": "Food Delivery Application",
  "main": "index.js",
  "scripts": {
    "start": "parcel index.html"
  },
  "author": "John",
  "license": "ISC"
}
```

---

# 📂 4. Understanding Every Field in `package.json`

---

## 📌 name

```json
"name": "food-ordering-app"
```

The name of your project.

---

## 📌 version

```json
"version": "1.0.0"
```

Current version of your application.

We'll learn versioning in detail in the next chapter.

---

## 📌 description

```json
"description": "Food Ordering Website"
```

A short description of your project.

---

## 📌 main

```json
"main": "index.js"
```

The main entry file of your package.

> **Note:** In React projects, this field is often ignored because tools like Parcel or Vite manage the entry point.

---

## 📌 scripts

```json
"scripts": {
    "start": "parcel index.html"
}
```

Scripts are shortcuts for terminal commands.

Instead of typing:

```bash
parcel index.html
```

You can simply run:

```bash
npm run start
```

npm executes:

```bash
parcel index.html
```

---

## Why are scripts useful?

Suppose your command is:

```bash
parcel src/index.html --port 3000
```

Typing it every time is tedious.

Instead:

```json
"scripts": {
    "dev": "parcel src/index.html --port 3000"
}
```

Now just run:

```bash
npm run dev
```

---

## 📌 author

```
"author": "Your Name"
```

Specifies the project's author.

---

## 📌 license

```
"license": "ISC"
```

Defines the licence under which your project is released.

For personal learning projects, you usually don't need to worry much about this.

# 📦 5. Installing Packages

Suppose you want React.

Run:

```bash
npm install react
```

or

```bash
npm i react
```

Both are identical.

---

## What happens?

```
Developer

↓

npm install react

↓

npm Registry

↓

Downloads React

↓

Creates node_modules

↓

Updates package.json

↓

Updates package-lock.json
```

---

## Example

Before:

```json
{
    "name": "food-ordering-app"
}
```

After installing React:

```json
{
    "dependencies": {
        "react": "^19.1.0"
    }
}
```

npm automatically updates the file.

---

# 🔄 6. How npm Installs Packages Internally

Suppose we run:

```bash
npm install axios
```

---

### Step 1

npm reads:

```
package.json
```

---

### Step 2

Connects to:

```
https://registry.npmjs.org
```

---

### Step 3

Downloads Axios.

---

### Step 4

Checks Axios dependencies.

Example:

```
Axios

↓

follow-redirects
```

If Axios depends on another package, npm downloads it too.

---

### Step 5

Creates:

```
node_modules/
```

---

### Step 6

Updates:

```
package-lock.json
```

---

### Final Folder Structure

```
📁 food-ordering-app

├── node_modules
├── package.json
├── package-lock.json
└── src
```

# 📌 7. Dependencies vs Dev Dependencies

There are two main types of packages.

## 📦 Dependencies

Installed using:

```bash
npm install react
```

These are required for your application to run.

Examples:

* React
* React DOM
* Axios
* React Router

Stored as:

```json
"dependencies": {
    "react": "^19.1.0"
}
```

---

## 🛠️ Dev Dependencies

Installed using:

```bash
npm install -D parcel
```

or

```bash
npm install --save-dev parcel
```

These are needed **only during development**.

Examples:

* Parcel
* Webpack
* ESLint
* Prettier
* Jest

Stored as:

```json
"devDependencies": {
    "parcel": "^2.16.4"
}
```

---

## Comparison Table

| Feature                    | Dependencies          | Dev Dependencies         |
| -------------------------- | --------------------- | ------------------------ |
| Needed in production?      | ✅ Yes                 | ❌ No                     |
| Needed during development? | ✅ Yes                 | ✅ Yes                    |
| Installed with             | `npm install package` | `npm install -D package` |
| Examples                   | React, Axios          | Parcel, ESLint, Jest     |

# 💡 Best Practices

✅ Always commit `package.json`.

✅ Use meaningful project names.

✅ Keep scripts simple.

✅ Install development tools as `devDependencies`.

# 🎤 Interview Questions

### Q1. What is `npm init`?

**Answer:**

`npm init` initialises a new Node.js project by creating a `package.json` file. It stores the project's metadata, scripts, and dependencies.

---

### Q2. What is the difference between `npm init` and `npm init -y`?

`npm init`

* Prompts you to answer setup questions.

`npm init -y`

* Automatically accepts default values and creates `package.json`.

---

### Q3. What is `package.json`?

`package.json` is the configuration file for a Node.js project. It stores project metadata, scripts, dependencies, and other configuration information.

---

### Q4. What is the difference between `dependencies` and `devDependencies`?

* **Dependencies** are required for the application to run.
* **Dev dependencies** are required only during development, such as bundlers, linters, and testing tools.

---

### Q5. What happens when you run `npm install react`?

A good interview answer:

1. npm reads `package.json`.
2. It connects to the npm registry.
3. It downloads the React package.
4. It resolves and downloads React's dependencies.
5. It stores everything inside `node_modules`.
6. It updates `package.json` and `package-lock.json`.

---

# 📝 Revision Notes

* 📦 `npm init` creates a new npm project.
* ⚡ `npm init -y` skips the setup questions.
* 📄 `package.json` is the configuration file for your project.
* 📥 `npm install package` adds a runtime dependency.
* 🛠️ `npm install -D package` adds a development dependency.
* 📂 `node_modules` stores the installed packages.
* 🔒 `package-lock.json` records the exact installed versions.

---

# 🎯 Key Takeaways

* 🚀 Every Node.js project starts with `npm init`.
* 📄 `package.json` acts as the blueprint for your project.
* 📦 npm automatically manages packages and their dependencies.
* 🛠️ Keep development tools in `devDependencies` and runtime libraries in `dependencies`.
* 📚 Understanding `package.json` is essential because almost every modern JavaScript project relies on it.
