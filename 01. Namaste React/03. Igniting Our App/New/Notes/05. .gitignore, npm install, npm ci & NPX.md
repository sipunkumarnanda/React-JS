# 📄 1. What is `.gitignore`?

Whenever we create a Git project

```bash
git init
```

Git starts tracking every file.

But...

Should Git track

```
node_modules/

.cache/

dist/

logs/
```

❌ No.

These files should not be uploaded.

That's where

```
.gitignore
```

comes in.

---

## Definition

`.gitignore` tells Git

> **"Ignore these files and folders."**

Git won't upload them.

---

## Example

```
Project

│

├── src

├── node_modules

├── package.json

├── package-lock.json

├── .gitignore

└── README.md
```

---

# 🤔 Why do we need `.gitignore`?

Suppose your project contains

```
node_modules

↓

700 MB
```

Imagine uploading

700 MB

every time you push.

Very slow.

Instead

Git uploads only

```
package.json

package-lock.json

src/
```

---

# Example `.gitignore`

```gitignore
node_modules

dist

.cache

.env

.DS_Store
```

# ⚖️ npm install vs npm ci

| npm install                  | npm ci                   |
| ---------------------------- | ------------------------ |
| Used in development          | Used in CI/CD            |
| Can update lock file         | Doesn't modify lock file |
| Slower                       | Faster                   |
| Installs compatible versions | Installs exact versions  |
| Works without package-lock   | Requires package-lock    |

# 📜 8. npm Scripts

Instead of writing

```bash
npx parcel src/index.html
```

every time

write

```json
{
    "scripts":{
        "start":"parcel src/index.html"
    }
}
```

Now run

```bash
npm run start
```

Much easier.

---

# Another Example

```json
{
  "scripts": {
      "dev":"parcel src/index.html",
      "build":"parcel build src/index.html"
  }
}
```

Development

```bash
npm run dev
```

Production

```bash
npm run build
```

# 🎤 Interview Questions

---

## Q1. What is `.gitignore`?

**Answer**

`.gitignore` is a file used by Git to specify which files and folders should not be tracked or committed to the repository.

---

## Q2. Why do we ignore `node_modules`?

**Answer**

Because it is very large and can always be recreated using `package.json` and `package-lock.json` by running `npm install`.

---

## Q3. Difference between `npm install` and `npm ci`?

**Answer**

`npm install` installs dependencies and may update the lock file.

`npm ci` installs dependencies exactly as specified in `package-lock.json` and is mainly used in CI/CD environments for faster, reproducible builds.

---

## Q4. What is `npx`?

**Answer**

`npx` executes npm packages without requiring a global installation. It can run locally installed packages or temporarily download and execute a package.

---

## Q5. Why do we use npm scripts?

**Answer**

npm scripts provide convenient shortcuts for frequently used commands, making projects easier to use and standardising common tasks such as development, building, testing, and linting.
