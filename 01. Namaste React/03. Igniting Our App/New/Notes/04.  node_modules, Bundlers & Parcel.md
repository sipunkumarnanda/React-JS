# 📦 1. What is `node_modules`?

Whenever we install a package using npm:

```bash
npm install react
```

or

```bash
npm install parcel
```

npm creates a folder called

```
node_modules
```

This folder contains **all the code of the installed packages**.

---

## Example

Suppose we install

```bash
npm install react
```

Our project becomes

```
Food-App

│

├── node_modules

│      └── react

├── package.json

└── package-lock.json
```

Notice that React's source code is now inside `node_modules`.

---

## Real World Analogy 🏠

Imagine building a house.

You order

* Cement
* Bricks
* Paint
* Steel

These materials arrive at your construction site.

Your project is the construction site.

`node_modules` is the **warehouse** where all the materials are stored.

```
Developer

↓

npm

↓

Warehouse (node_modules)

↓

Project
```

# 🤔 2. Why is `node_modules` So Large?

This surprises almost every beginner.

You install only one package:

```bash
npm install parcel
```

But your `node_modules` folder contains **hundreds or even thousands** of packages.

Why?

Because packages depend on other packages.

Example:

```
Parcel

↓

Babel

↓

Source Maps

↓

Utilities

↓

Other Packages
```

This chain continues.

---

## Example Dependency Tree

```
Your Project

│

└── Parcel

      │

      ├── Babel

      │      │

      │      ├── Core JS

      │      └── Parser

      │

      ├── PostCSS

      │

      └── SWC
```

Although you installed **one** package, npm downloaded **many**.

# ❌ 4. Why Don't We Upload `node_modules` to GitHub?

One of the most common interview questions.

---

## Imagine

Your project

```
20 MB
```

But

```
node_modules

↓

650 MB
```

Uploading hundreds of megabytes to GitHub is unnecessary.

---

## Why?

Because all the required information already exists inside

```
package.json

+

package-lock.json
```

These two files tell npm

* Which packages are required
* Which versions should be installed

So there's no need to upload the packages themselves.

---

## Real World Analogy 📚

Imagine sending a recipe to a friend.

Instead of sending

* Tomatoes
* Onions
* Salt
* Oil

you simply send the recipe.

Your friend buys the ingredients locally.

`package.json` is the recipe.

`node_modules` are the ingredients.

# 🙈 5. How Can We Recreate `node_modules`?

Suppose someone clones your repository.

Initially

```
Food App

│

├── package.json

├── package-lock.json

└── src
```

No `node_modules`.

Simply run

```bash
npm install
```

npm reads

```
package.json

↓

package-lock.json

↓

Downloads Packages

↓

Creates node_modules
```

Done.

# 📦 6. What is a Bundler?

Imagine your React project contains

```
200 JavaScript Files

150 CSS Files

100 Images

50 Fonts
```

If the browser downloads every file separately

↓

The website becomes slow.

A bundler solves this problem.

---

## Definition

A **bundler** combines and optimises your project files so they can be delivered efficiently to the browser.

---

## Before Bundling

```
App

│

├── Home.js

├── Login.js

├── Navbar.js

├── Footer.js

├── Utils.js

├── style.css

├── icons.svg

└── ...
```

---

## After Bundling

```
dist

│

├── index.html

├── main.js

├── style.css

└── images
```

The browser now downloads fewer, optimised files.

---

# 🚀 7. Why Do We Need a Bundler?

A bundler does much more than just combine files.

It also:

* 🗜️ Minifies JavaScript
* 📦 Bundles files
* 🖼️ Compresses images
* ⚡ Optimises assets
* 🌳 Performs tree shaking
* 📂 Splits code into smaller chunks
* 🧠 Caches builds
* 🔄 Handles module resolution

Without a bundler, modern JavaScript development would be much more difficult.

# 🚀 9. What is Parcel?

Parcel is a **zero-configuration web application bundler**.

This means:

You install it:

```bash
npm install -D parcel
```

Then run:

```bash
npx parcel index.html
```

No configuration is required for most projects.

---

# ⚡ 10. Why is Parcel Fast?

Parcel is fast because it includes several optimisations:

### ✅ Caching

After the first build, Parcel stores build information in its cache.

The next build only rebuilds changed files.

---

### ✅ Parallel Processing

Parcel can process multiple files at the same time using multiple CPU cores.

---

### ✅ Incremental Builds

Only modified files are rebuilt.

Not the entire project.

---

### ✅ Optimised Dependency Graph

Parcel understands relationships between modules and rebuilds only what is necessary.

# 🌐 13. Development Server

Parcel automatically starts a local server.

Example:

```
http://localhost:1234
```

Whenever you save a file, Parcel rebuilds the necessary parts and updates the browser.

---

# 🔥 14. Hot Module Replacement (HMR)

Imagine you change:

```jsx
<h1>Hello</h1>
```

to

```jsx
<h1>Hello React</h1>
```

Without HMR:

* Entire page reloads
* Application state may be lost

With HMR:

* Only the changed module is updated
* The rest of the application stays running

This speeds up development and often preserves state.

---

# 👀 15. File Watching

Parcel watches your project files continuously.

```
Developer Saves File

↓

Parcel Detects Change

↓

Rebuilds Only What Changed

↓

Browser Updates
```

No manual refresh is required.

---

# 🏭 16. Production Build

During development:

```bash
npx parcel index.html
```

During production:

```bash
npx parcel build index.html
```

Parcel then:

* Minifies code
* Optimises images
* Removes unused code
* Compresses assets
* Generates production-ready files

The output is placed in the `dist` folder by default.

# 💡 Best Practices

* ✅ Add `node_modules` to `.gitignore`.
* ✅ Commit `package.json` and `package-lock.json`.
* ✅ Use a bundler for production builds.
* ✅ Don't edit files inside `node_modules`.
* ✅ Use production builds when deploying.

# 🎤 Interview Questions

### Q1. What is `node_modules`?

**Answer:**

`node_modules` is the directory where npm stores all installed packages and their dependencies. It contains the actual code required by your project.

---

### Q2. Why is `node_modules` so large?

**Answer:**

Because installed packages have their own dependencies, which in turn have additional dependencies. npm installs the entire dependency tree.

---

### Q3. Why don't we push `node_modules` to GitHub?

**Answer:**

It's large and can be recreated at any time using `package.json` and `package-lock.json`. Committing it would unnecessarily increase repository size.

---

### Q4. What is a bundler?

**Answer:**

A bundler processes project files, resolves dependencies, and creates optimised bundles for development and production. It also performs tasks such as minification, code splitting, and asset optimisation.

---

### Q5. Why is Parcel popular?

**Answer:**

Parcel is popular because it requires little or no configuration, provides a fast development experience, supports Hot Module Replacement, and performs many optimisations automatically.
