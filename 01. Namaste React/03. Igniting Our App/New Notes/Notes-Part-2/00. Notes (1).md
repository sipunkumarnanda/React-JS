* No, React alone is not responsible for making our application fast.

* There are many other tools and optimizations involved that help improve the performance of our application.

# 📦 What is npm?

* npm stands for **Node Package Manager**.

* It is a package manager for Node.js that manages all the packages and dependencies we install in our project.

---

# 📥 How to use npm in your project?

* We can initialize npm in our project using the command:

```bash
npm init -y
```

* This command creates a `package.json` file with default configuration.

---

# 📄 What is package.json?

* The `package.json` file is the configuration file for npm.

* It is written in JSON format.

* It contains information about:

  * Project details
  * Dependencies
  * Dev dependencies
  * Scripts
  * Package versions

---

# 📦 Downloaded packages have dependencies

* Our project depends on many packages.

* Those packages can also depend on many other packages.

* These dependencies inside dependencies are managed by npm.

Example:

```
Our Project

↓

Parcel

↓

Babel

↓

Other Packages

↓

More Packages
```

* npm manages all these dependencies automatically.

* npm also takes care of the versions of these packages.

* All this information is stored inside `package.json` and `package-lock.json`.

---

# 📦 What is a Bundler?

* A bundler combines all our project files and prepares them for production.

* A bundler performs tasks like:

  * Bundling JavaScript files
  * Minifying code
  * Compressing images
  * Optimizing assets
  * Caching files

Examples of bundlers:

* Webpack

* Parcel

* Vite

* Create React App uses Webpack internally behind the scenes.

# 📦 Types of Dependencies

There are two types of dependencies:

## 1. Dev Dependencies

* These are packages required during the development of our project.

Examples:

* Parcel
* Testing tools
* Linters

Example:

```json
"devDependencies": {
  "parcel": "^2.16.4"
}
```

---

## 2. Normal Dependencies

* These are packages required when our application runs in production.

Examples:

* React
* ReactDOM
* Axios

# 🔢 What is `^` (Caret)?

Example:

```json
"parcel": "^2.16.4"
```

The caret (`^`) allows npm to install newer **minor and patch versions** but keeps the same major version.

Allowed:

```
2.16.5 ✅
2.17.0 ✅
2.20.0 ✅
```

Not allowed:

```
3.0.0 ❌
```

Because a major version can introduce breaking changes.

---

# 🔢 Difference between `~` and `^`

## `^` Caret

Allows:

* Minor updates
* Patch updates

Example:

```
^2.16.4

2.17.0 ✅
2.18.0 ✅
```

---

## `~` Tilde

Allows only:

* Patch updates

Example:

```
~2.16.4

2.16.5 ✅
2.16.6 ✅
```

Not allowed:

```
2.17.0 ❌
```

---

# 📄 What is package-lock.json?

* `package-lock.json` keeps track of the exact versions of packages installed in our project.

* It ensures that every developer and production environment gets the same package versions.

Example:

`package.json`

```json
"parcel": "^2.16.4"
```

means:

"Install a compatible version."

But:

`package-lock.json`

stores:

```
parcel: 2.16.4
```

meaning:

"Install exactly this version."

---

# 🔐 What is the integrity hash?

Example inside `package-lock.json`:

```json
"integrity": "sha512-Nb8peNvh..."
```

* This hash is used to verify that the downloaded package is exactly the same as the original package.

* It helps prevent issues like:

> "It works on my machine but not on production."

* When installing packages, npm checks this hash to confirm that the package has not been corrupted or modified.

# 📦 What is node_modules?

* `node_modules` contains all the packages and dependencies downloaded from the npm registry.

Example:

When we install:

```bash
npm install parcel
```

we get:

```
node_modules

↓

parcel

↓

parcel dependencies

↓

other dependencies
```

---

# 🤔 Why are there many packages inside node_modules when we installed only Parcel?

Because:

* Our project depends on Parcel.

* Parcel depends on many other packages.

* Those packages also depend on other packages.

This creates many layers of dependencies.

This is called:

## Transitive Dependencies

Example:

```
Project

↓

Parcel

↓

Babel

↓

Another Package

↓

Another Package
```

---

# 🌳 What is a Dependency Tree?

* Every package inside `node_modules` can have its own `package.json`.

* Inside that `package.json`, we can see its dependencies.

* This creates a tree-like structure called a **dependency tree**.

Example:

```
Project

├── Parcel
│
├── Babel
│
├── PostCSS
│
└── Other Packages
```

---

# 📦 Should we push node_modules to GitHub or production?

* No.

* The `node_modules` folder can be extremely large.

* It can be recreated anytime using:

```bash
npm install
```

* Therefore, we add it to `.gitignore`.

Example:

```
node_modules/
```

---

# 📄 Should we put package.json and package-lock.json inside `.gitignore`?

* No.

* We should always push both files to GitHub.

Why?

Because they contain important information about:

* Project dependencies
* Package versions
* Project configuration

---

# 🔄 If we don't push node_modules, how will we generate it later?

* We can recreate `node_modules` using:

```bash
npm install
```

* npm reads:

```
package.json

+

package-lock.json

↓

Downloads dependencies

↓

Creates node_modules
```
